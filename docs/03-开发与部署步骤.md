# 开发与部署步骤

## 一、环境要求

| 用途 | 需要 | 本项目实测版本 |
|---|---|---|
| 开发 / 构建网页版 | Node.js ≥ 22.13（pdfjs-dist v6 的要求） | Node 24.15.0 |
| 包管理 | npm（或 pnpm） | npm 11.x |
| 打安卓 APK | **JDK 21**、Android SDK（platform 36 + build-tools 36） | JDK 21.0.12 / Gradle 8.14.3 / AGP 8.13 |

> 💡 只想用网页版的话，**不需要** Java 和 Android SDK。

> ⚠️ **必须是 JDK 21**。Capacitor 8 的安卓模板要求 `sourceCompatibility JavaVersion.VERSION_21`，用 JDK 17 会直接构建失败。

---

## 二、本地开发

```bash
npm install
npm run dev
```

会启动 Vite 开发服务器（默认 http://localhost:5173）。

### 在手机上调试
1. 手机和电脑连同一个 WiFi；
2. 看终端里的 `Network` 地址（形如 `http://192.168.1.10:5173`）；
3. 手机浏览器打开它 → 浏览器菜单里选「添加到主屏幕」。

这样就跟装了 App 差不多（全屏、有图标、离线可打开）。

### 常用命令

| 命令 | 作用 |
|---|---|
| `npm run dev` | 开发服务器（热更新） |
| `npm run typecheck` | TypeScript 类型检查（src + 构建配置两个工程） |
| `npm test` | 跑单元测试（96 个用例，含完整闭环集成测试） |
| `npm run test:watch` | 单元测试监听模式 |
| `npm run probe:cors` | 探测各家大模型接口是否允许浏览器直连（不需要 API Key） |
| `npm run build` | 类型检查 + 生产构建到 `dist/` |
| `npm run build:fast` | 跳过类型检查直接构建（应急用） |
| `npm run build:single` | 生成单文件离线版 `dist-single/single.html` |
| `npm run serve` | 用内置极简服务器预览 `dist/`（默认 4173 端口） |
| `npm run cap:sync` | 构建网页产物并同步进安卓工程 |
| `npm run apk` | 一键构建调试版 APK（需 JDK 21 + Android SDK） |
| `npm run apk:release` | 构建正式版 APK（需先配签名） |
| `npm run preview` | 用 Vite 预览构建产物 |
| `npm run icons` | 重新生成 PWA 图标 + 安卓图标/启动页 |

## 三、部署网页版

`npm run build` 之后，`dist/` 是**纯静态文件**，扔到哪都能跑：

- **GitHub Pages**：把 `dist/` 推到 `gh-pages` 分支；
- **Vercel / Netlify**：构建命令 `npm run build`，发布目录 `dist`；
- **自己的 NAS / 服务器**：用 nginx 之类托管 `dist/`，注意 SPA 需要把所有路径回退到 `index.html`。

> ⚠️ 本项目用的是 `HashRouter`（地址里带 `#`），所以**不需要**配置服务端回退，放静态托管最省事。

## 四、打包安卓 APK

Capacitor 已经把 `dist/` 包进安卓壳，**`android/` 工程目录已经生成好了**。你要做的只是准备好工具链，然后一条命令出包。

### 4.1 准备工具链（只需一次）

| 组件 | 版本要求 | 说明 |
|---|---|---|
| JDK | **21** | Capacitor 8 要求；用 JDK 17 会构建失败 |
| Android SDK Platform | `android-36` | compileSdk = 36 |
| Android SDK Build-Tools | `36.0.0` | |
| Android SDK Platform-Tools | 最新 | 可选，用来 `adb` 装包 |

**装法一（推荐）**：装 [Android Studio](https://developer.android.com/studio)，它会顺手装好 JDK 和 SDK。

**装法二（只要命令行）**：

```bash
# 1) 装 JDK 21（Eclipse Temurin）
#    https://adoptium.net/temurin/releases/?version=21
# 2) 装 cmdline-tools，然后用 sdkmanager 装组件
sdkmanager "platform-tools" "platforms;android-36" "build-tools;36.0.0"
```

设置环境变量并验证：

```
JAVA_HOME=<JDK 21 路径>
ANDROID_HOME=<Android SDK 路径>
PATH=%PATH%;%ANDROID_HOME%\platform-tools
```

```bash
java -version    # 必须显示 21.x
adb version      # 可选
```

> 💡 项目还支持一种"免安装"约定：把 JDK 和 SDK 放到**仓库同级的 `.android-tools/`** 目录里
> （`jdk-21/` 与 `android-sdk/`），`npm run apk` 会自动找到它们，不用配环境变量。
>
> 没有 Android Studio、或者网络受限装不上 SDK 时，仓库里有现成脚本：
>
> ```bash
> node scripts/setup-android-toolchain.mjs
> ```
>
> 它会自动下载 JDK 21、cmdline-tools、platform-tools、platform-36、build-tools 36.0.0，
> 解压并铺成标准 SDK 目录结构（含许可证文件），全程只依赖 Node，不写系统目录。

### 4.2 出包

```bash
npm run apk            # 调试版，产物在 android/app/build/outputs/apk/debug/
npm run apk:release    # 正式版，需要先配好签名
```

脚本会自动：① 构建网页产物 → ② `cap sync` 同步进安卓工程 → ③ 调 Gradle 打包 → ④ 打印产物路径和 adb 安装命令。

也可以手工来：

```bash
npm run build:fast
npx cap sync android
cd android && ./gradlew assembleDebug      # Windows 用 gradlew.bat assembleDebug
```

### 4.3 装到手机

```bash
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

或者把 APK 拷到手机上点击安装（首次需要允许"安装未知来源应用"）。

### 4.4 关于体积

包内含 `pdfjs`（约 1.3 MB）与 React（约 0.7 MB），APK 通常在 5~10 MB。

### 4.5 排障

<details>
<summary><b><code>sdkmanager</code> 报 "Failed to download any source lists" / "IO exception while downloading manifest"</b></summary>

某些网络环境下 `sdkmanager` 拉不到 Google 的仓库清单。绕开办法是**直接下载组件压缩包，手工铺成 SDK 目录结构**：

```
<SDK>/
├─ cmdline-tools/latest/     ← commandlinetools-win-*.zip 解压后，把内层 cmdline-tools/* 放进来
├─ platform-tools/           ← platform-tools-latest-windows.zip（内层就叫 platform-tools）
├─ platforms/android-36/     ← platform-36_r01.zip（内层就叫 android-36）
├─ build-tools/36.0.0/       ← build-tools_r36_windows.zip（内层叫 android-16，**必须改名成 36.0.0**）
└─ licenses/
   ├─ android-sdk-license
   └─ android-sdk-preview-license
```

`licenses/android-sdk-license` 写入这三行：

```
8933bad161af4178b1185d1a37fbf41ea5269c55
d56f5187479451eabf01fb78af6dfcb131a6481e
24333f8a63b6825ea9c5514f83c2829b004d1fee
```

`licenses/android-sdk-preview-license` 写入：`84831b9409646a918e30573bab4c9c91346d8abd`

铺好后用 `sdkmanager --list_installed` 验证能否识别到这三个包。

国内镜像：把 `https://dl.google.com/android/repository/` 换成
`https://mirrors.cloud.tencent.com/AndroidSDK/`（文件名相同）。
</details>

<details>
<summary><b>Gradle 报 <code>Could not determine java version</code> 或 <code>Unsupported class file major version</code></b></summary>

JDK 版本不对。Capacitor 8 的模板写死了 `sourceCompatibility JavaVersion.VERSION_21`，
必须用 JDK 21。用 `java -version` 确认，并检查 `JAVA_HOME` 指向的是 21 而不是 17。
</details>

## 五、GitHub Actions 自动打包

仓库里**已经配好了** [`.github/workflows/android.yml`](../.github/workflows/android.yml)：
推到 `v*` 标签时自动构建 APK 并挂到 Release，也可以在 Actions 页面手动触发。

它做的事：装 Node → 装 JDK 21 → 装 Android SDK → `npm ci` → 类型检查 → 构建 → `cap sync` → `gradlew assembleDebug` → 上传产物（tag 触发时同时挂 Release）。

想改的话，直接编辑那个文件即可。

## 六、发布到 GitHub

仓库**已经在本地初始化好了**（4 个提交，`v0.1.0` ~ `v0.3.0` 三个标签）。
发布只差一个 Token。

### 推荐：用脚本一条命令搞定

```powershell
$env:GITHUB_TOKEN = "ghp_xxxxxxxx"            # 勾选 repo + workflow 权限
$env:GITHUB_PROXY = "http://127.0.0.1:7890"   # 仅国内直连被重置时需要
node scripts/publish-github.mjs               # 或 npm run publish:github
```

脚本会依次：校验 Token → 读取账号 → 建仓（已存在就跳过）→ 配置 `origin`
→ 推送当前分支与**全部标签**，最后打印仓库地址和后续建议。

> 🔒 Token 只通过环境变量传入，**不会**写进代码，也**不会**留在 `.git/config` 里
> —— 推送时用 `git -c http.extraHeader` 临时携带凭据，用完即弃。
> 建议用完后到 [设置页](https://github.com/settings/tokens) 删掉该 Token。

可选参数：

| 环境变量 | 作用 |
|---|---|
| `GITHUB_REPO` | 仓库名，默认 `electro-tutor` |
| `GITHUB_PRIVATE=1` | 建私有仓库 |
| `GITHUB_PROXY` | 形如 `http://127.0.0.1:7890` |

### 手工方式

```bash
git remote add origin https://github.com/<用户名>/electro-tutor.git
git push -u origin main
git push origin --tags        # 把 v0.1.0 ~ v0.3.0 一起推上去，方便回滚到可用版本
```

推完标签后，如果启用了 GitHub Actions，`v*` 标签会自动触发构建并发布 APK 到 Release。

### 如果 GitHub 连不上

国内直连 GitHub 常被重置。如果本地有代理（比如 Clash 监听 7890），配置：

```bash
git config --global http.proxy http://127.0.0.1:7890
git config --global https.proxy http://127.0.0.1:7890
```

如果报 `schannel: AcquireCredentialsHandle failed` 或 `Recv failure`，说明是 Windows 的 TLS 后端问题，换成 OpenSSL 后端：

```bash
git config --global http.sslBackend openssl
```

用完想取消代理：

```bash
git config --global --unset http.proxy
git config --global --unset https.proxy
```

## 七、常见问题

<details>
<summary><b>构建时报 <code>spawn EPERM</code>（Vite 执行 net use 探测网络驱动器）</b></summary>

Vite 在 Windows 上会执行 `net use` 并用管道读取输出，用来判断项目是否在网络驱动器上。某些受限环境（沙箱 / 严格安全策略）禁止子进程管道，就会抛 EPERM。

解决办法：在**普通终端**里运行构建（不要用受限沙箱），或者改用 WSL。
</details>

<details>
<summary><b>手机浏览器里调用大模型报"网络请求被拦截"</b></summary>

见 README 的「如果提示"网络请求被拦截"」一节。
</details>

<details>
<summary><b><code>npm install</code> 报权限错误、写不进 npm 缓存</b></summary>

把缓存目录指到项目内：

```bash
npm config set cache ./.npm-cache --location=project
npm install
```
</details>
