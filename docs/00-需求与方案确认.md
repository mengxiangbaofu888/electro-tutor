## 二、必须先说清楚的 4 个技术现实

### 2.1 大模型**看不了**视频链接（最关键）
把 `https://www.bilibili.com/video/BVxxx` 丢给 GPT/DeepSeek/通义，它打不开这个网页，更看不到画面和声音。
必须先把视频"变成文字"或"变成图"，才能喂给模型。可行路径（详见 §4.1）：

| 方案 | 可行性 | 说明 |
|---|---|---|
| A. 抓视频**官方字幕/CC** | 高（B站/YouTube 有接口） | 有字幕就最省事最准；无字幕就抓不到 |
| B. 你**手动粘贴**字幕/讲义文本 | 高（100%可用） | 最土但最稳，兜底方案 |
| C. 上传**讲义文档**（PDF/PPT/Word） | 高 | 大多数网课都有配套讲义，exameow 走的就是这条路 |
| D. **截图/拍照 → 视觉模型**识别 | 中高 | 电工有电路图/公式，截图会比 OCR 更靠谱，需支持视觉的模型 |
| E. 下载音频跑 **ASR 转写** | 低（手机端不现实） | 手机本地跑不动 Whisper；云端 ASR 要另付费、还要后端 |

**我的建议**：A+C+D+B 全做，B 永远兜底。**不承诺"给个链接就全自动"**，而是"有字幕/讲义就自动，没有就提示你贴文本或截图"。

### 2.2 本机现在**没有**安卓构建环境
实测：`java` 无、`ANDROID_HOME` 无、`gradle` 无、也没有 Android Studio。有的：Node v24、pnpm、Python 3.12、git 2.53。
打一个真 APK 需要 JDK 17 + Android SDK（约 2–4 GB 下载）。三条路：

1. **本机装 JDK+SDK，本地打包**（推荐）：一次性下载 2–4 GB，之后每改一版几分钟出包，迭代最快。
2. **GitHub Actions 云打包**：本机啥都不用装，推代码后云端出 APK，从 Release 下载。缺点是每轮要等几分钟、且本地无法先验证。
3. **先做 PWA（网页版）立即可用 + 再套壳成 APK**：先在手机 Chrome 里"添加到主屏幕"就能用，零环境；确认功能 OK 后再套壳出正式 APK。

**我的建议**：代码写成"Web App 内核 + Capacitor 套壳"，先用 1 或 3 跑起来，最后出 APK + 同时配好 GitHub Actions 自动打包。

### 2.3 网络：GitHub 直连被重置，必须走你的代理
实测结论：
- 系统代理 `127.0.0.1:7890`（Clash 之类）**在监听且可用**。
- `curl.exe` / git 默认的 Windows schannel TLS 后端**报错**（`SEC_E_NO_CREDENTIALS`）——这是 TLS 后端问题，不是网络问题。
- 修复方式已验证有效：`git config --global http.sslBackend openssl` + `http.proxy=http://127.0.0.1:7890`，能正常访问 GitHub。
- Node/npm 的 TLS 正常，`npm ping` 通、Node `fetch` 能直接读 GitHub API。

所以"发布到 GitHub"没问题，我会自动带上代理和 OpenSSL 后端参数。

### 2.4 需要你的两把"钥匙"
- **大模型 API Key**（本机环境变量里没有任何 key）
- **GitHub 账号的 Personal Access Token**（本机没有 `gh` 命令行，也没有存过任何 git 凭据）

Key 只存在手机本地（App 设置页里填），**不会**写进代码、不会推到 GitHub。

## 三、功能设计

### 3.1 输入层（"喂料"）
- 粘贴**网页/文章链接** → 抓正文 → 转 Markdown
- 粘贴**视频链接** → 尝试抓官方字幕；抓不到 → 引导你贴字幕 / 传讲义 / 截图
- 上传**文档**：PDF / PPTX / DOCX / TXT / Markdown（exameow 支持的一整套）
- **拍照/相册截图** → 视觉模型转文字/识图（电路图、公式）
- 手动粘贴文本（万能兜底）

### 3.2 出题与考试
- **大纲生成**：把材料切块 → 提炼知识点树（二级/三级）→ 标注难度与重要度 → 你可手动增删
- **出题**：单选 / 多选 / 判断 / 填空 / 简答 / **计算题**（电工必备）
- **组卷**：按知识点范围、题型配比、数量、难度、时间生成卷子
- **答题**：App 内作答，支持草稿、标记、倒计时
- **阅卷**：
  - 客观题 → 本地判分（免费、离线、100% 准）
  - 主观/计算题 → AI 按"评分点"逐步给分 + 解析 + 常见错误提醒；**你可申诉**让 AI 重判
- **题库 / 错题本 / 重做**

### 3.3 "自进化"我准备这样做（请确认含义）
我理解成**应用层的学习闭环**，而不是"训练模型"（训练/微调模型成本极高，不现实）。四个机制：

1. **知识点掌握度模型**：每题挂知识点标签；答题结果更新每个知识点的掌握分（带遗忘衰减）。
2. **间隔重复排程**：错题/薄弱点按记忆曲线（SM-2 / FSRS 类算法）自动安排复习时间。
3. **自适应出题**：下一张卷子自动提高薄弱知识点的占比，并做难度爬坡。
4. **学习者画像自动迭代**：把"你总在哪类题上错、错因是什么、什么讲法你听得懂"沉淀成一份**画像 Prompt**，每次出题/讲解时自动注入 —— 于是它越用越懂你。

> 进阶可选（成本更高，待定）：针对薄弱点自动生成"补强微讲义 + 3 道即时巩固题"。

### 3.4 明确**不做**（避免误解）
- ❌ 不下载/不搬运受版权保护的视频本体
- ❌ 不训练或微调大模型
- ❌ 不做多人考场/监考（exameow 的考试码那套；除非你要）
- ❌ 不需要服务器（local-first，零部署成本；Key 和数据都在你手机上）

## 四、技术方案

### 4.1 技术选型（建议）
| 层 | 选择 | 理由 |
|---|---|---|
| 前端 | React + TypeScript + Vite | 生态成熟、我能快速迭代、便于做 PWA |
| 本地数据 | IndexedDB（Dexie） | 题库/错题/掌握度全离线，隐私好 |
| 安卓壳 | **Capacitor**（对比 Tauri） | 本机已有 Node，无需 Rust + NDK；Capacitor 原生 HTTP 可绕开 CORS，抓字幕/抓网页更顺 |
| 打包 | 本地 Gradle + GitHub Actions 双通道 | 本地迭代快，云端留档/自动出 Release |
| 大模型 | OAI 兼容协议，预置 DeepSeek / 通义千问 / 智谱 GLM / 豆包 / Ollama | 与 exameow 一致，你可随时换 |
| 视觉模型 | 通义千问-VL / GLM-4V / 豆包 vision（可选配） | 识电路图、公式截图 |

### 4.2 项目结构（草案）
```
electro-tutor/
├─ docs/                    # 需求、架构、步骤文档（GitHub 备份的一部分）
├─ src/                     # Web App 源码
│  ├─ features/ingest/      # 链接/文档/截图 → 文本
│  ├─ features/outline/     # 大纲生成
│  ├─ features/quiz/        # 出题/组卷/答题
│  ├─ features/grade/       # 判分/AI 批改
│  ├─ features/insight/     # 薄弱点/报告/自进化引擎
│  ├─ features/settings/    # 模型配置
│  └─ lib/llm/              # 大模型适配层
├─ android/                 # Capacitor 生成的安卓工程
├─ .github/workflows/       # 自动打包 APK
└─ README.md
```

### 4.3 分阶段实施（里程碑）
| 阶段 | 内容 | 你能得到什么 |
|---|---|---|
| **M0** | 建 Git 仓库 + 项目骨架 + GitHub 备份打通 | 代码已在 GitHub 有备份 |
| **M1** | 设置页（填 Key/模型）+ 材料导入（文本/文档/截图）→ 大纲生成 | 能给一段材料出知识大纲 |
| **M2** | 出题 + 组卷 + 答题界面 | 能做题了 |
| **M3** | 判分（客观本地 + 主观 AI）+ 学习报告 + 薄弱点分析 | 完整闭环，可以开始用 |
| **M4** | 自进化四机制（掌握度/间隔重复/自适应出题/画像迭代） | 越用越准 |
| **M5** | 出 APK（本地） + GitHub Actions 云打包 + Release + 完整文档 | 手机装上用，GitHub 上有备份和安装包 |
| **M6**（可选） | 视频字幕抓取、补强微讲义、错题导出 | 体验升级 |

### 4.4 GitHub 备份方案
1. 我把项目代码 + `docs/`（含需求、架构、开发步骤、使用说明）整理成仓库
2. 推送（走 OpenSSL + 代理）
3. 配 GitHub Actions：推 tag 自动出 APK 并挂到 Release
4. README 写清楚：这是什么、怎么配 Key、怎么装、怎么自己打包
5. 按里程碑打 tag（v0.1 / v0.2 …），每个可用版本都有备份点
