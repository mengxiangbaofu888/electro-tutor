# 开发与部署步骤

## 一、环境要求

| 用途 | 需要 | 本项目实测版本 |
|---|---|---|
| 开发 / 构建网页版 | Node.js ≥ 22.13（pdfjs-dist v6 的要求） | Node 24.15.0 |
| 包管理 | npm（或 pnpm） | npm 11.x |
| 打安卓 APK | JDK 17+、Android SDK | 见第四节 |

> 💡 只想用网页版的话，**不需要** Java 和 Android SDK。

---

## 二、本地开发

```bash
npm install
npm run dev
```

会启动 Vite 开发服务器（默认 http://localhost:5173）。

### 在手机上调试
1. 手机和电脑连同一个 WiFi；
2. 看终端里的 `Network` 地址（形如 `http://192.168.1.10:5173`）；
3. 手机浏览器打开它 → 浏览器菜单里选「添加到主屏幕」。

这样就跟装了 App 差不多（全屏、有图标、离线可打开）。

### 常用命令

| 命令 | 作用 |
|---|---|
| `npm run dev` | 开发服务器（热更新） |
| `npm run typecheck` | TypeScript 类型检查（src + 构建配置两个工程） |
| `npm run build` | 类型检查 + 生产构建到 `dist/` |
| `npm run build:fast` | 跳过类型检查直接构建（应急用） |
| `npm run build:single` | 生成单文件离线版 `dist-single/single.html` |
| `npm run serve` | 用内置极简服务器预览 `dist/`（默认 4173 端口） |
| `npm run preview` | 用 Vite 预览构建产物 |
| `npm run icons` | 重新生成 PWA 图标 |

## 三、部署网页版

`npm run build` 之后，`dist/` 是**纯静态文件**，扔到哪都能跑：

- **GitHub Pages**：把 `dist/` 推到 `gh-pages` 分支；
- **Vercel / Netlify**：构建命令 `npm run build`，发布目录 `dist`；
- **自己的 NAS / 服务器**：用 nginx 之类托管 `dist/`，注意 SPA 需要把所有路径回退到 `index.html`。

> ⚠️ 本项目用的是 `HashRouter`（地址里带 `#`），所以**不需要**配置服务端回退，放静态托管最省事。

## 四、打包安卓 APK

思路：用 **Capacitor** 把 `dist/` 包进一个安卓壳。这样网页和 App 共用同一套代码。

### 4.1 安装 JDK 17 和 Android SDK

1. **JDK 17**：装 [Eclipse Temurin 17](https://adoptium.net/temurin/releases/?version=17)，装完设好 `JAVA_HOME`。
2. **Android SDK**：装 [Android Studio](https://developer.android.com/studio)，或者只装命令行工具（`cmdline-tools`），然后：
   ```bash
   sdkmanager "platform-tools" "platforms;android-35" "build-tools;35.0.0"
   ```
3. 设置环境变量：
   ```
   ANDROID_HOME=<你的 Android SDK 路径>
   PATH=%PATH%;%ANDROID_HOME%\platform-tools
   ```
4. 验证：
   ```bash
   java -version
   adb version
   ```

### 4.2 加 Capacitor

```bash
npm install @capacitor/core @capacitor/cli @capacitor/android
npx cap init "电工陪练" com.electrotutor.app --web-dir=dist
npm run build
npx cap add android
npx cap sync
```

### 4.3 关键配置

**`capacitor.config.ts`** 里建议加上（让 App 内的请求走原生、避开跨域）：

```ts
const config: CapacitorConfig = {
  appId: 'com.electrotutor.app',
  appName: '电工陪练',
  webDir: 'dist',
  android: {
    allowMixedContent: true,
  },
  plugins: {
    CapacitorHttp: { enabled: true },
  },
};
```

> 代码里已经做了适配：检测到运行在原生环境时会自动使用 `CapacitorHttp`，**不需要改业务代码**。

### 4.4 出包

```bash
cd android
./gradlew assembleDebug        # 调试包，产物在 app/build/outputs/apk/debug/
./gradlew assembleRelease      # 正式包，需要先配签名
```

或者用 Android Studio 打开 `android/` 目录，菜单 **Build → Build Bundle(s) / APK(s)**。

### 4.5 关于 APK 体积

包内含 `pdfjs`（约 1.3 MB）和 React（约 0.7 MB），所以 APK 大概在 5~10 MB。想瘦身可以在 `vite.config.ts` 里把 `pdfjs-dist` 改成按需动态加载。

## 五、GitHub Actions 自动打包

推到 tag 时自动出 APK 并挂到 Release。创建 `.github/workflows/android.yml`：

```yaml
name: Build Android APK

on:
  push:
    tags: ['v*']
  workflow_dispatch:

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm

      - uses: actions/setup-java@v4
        with:
          distribution: temurin
          java-version: '21'

      - uses: android-actions/setup-android@v3

      - run: npm ci
      - run: npm run build

      - run: npx cap sync android

      - name: Build debug APK
        run: |
          cd android
          chmod +x gradlew
          ./gradlew assembleDebug

      - uses: actions/upload-artifact@v4
        with:
          name: electro-tutor-apk
          path: android/app/build/outputs/apk/debug/*.apk

      - name: Attach to release
        if: startsWith(github.ref, 'refs/tags/')
        uses: softprops/action-gh-release@v2
        with:
          files: android/app/build/outputs/apk/debug/*.apk
```

> 这个 workflow 要在**加了 Capacitor 之后**才会成功（现在仓库里还没有 `android/` 目录）。

## 六、用 Git 备份到 GitHub

```bash
git init
git add .
git commit -m "feat: 电工陪练 v0.1 - 材料导入/大纲/出题/批改/自进化闭环"
git branch -M main
git remote add origin https://github.com/<用户名>/electro-tutor.git
git push -u origin main
```

打标签，方便以后回滚到可用版本：

```bash
git tag -a v0.1.0 -m "第一个可用版本：完整学习闭环"
git push origin v0.1.0
```

### 如果 GitHub 连不上

国内直连 GitHub 常被重置。如果本地有代理（比如 Clash 监听 7890），配置：

```bash
git config --global http.proxy http://127.0.0.1:7890
git config --global https.proxy http://127.0.0.1:7890
```

如果报 `schannel: AcquireCredentialsHandle failed` 或 `Recv failure`，说明是 Windows 的 TLS 后端问题，换成 OpenSSL 后端：

```bash
git config --global http.sslBackend openssl
```

用完想取消代理：

```bash
git config --global --unset http.proxy
git config --global --unset https.proxy
```

## 七、常见问题

<details>
<summary><b>构建时报 <code>spawn EPERM</code>（Vite 执行 net use 探测网络驱动器）</b></summary>

Vite 在 Windows 上会执行 `net use` 并用管道读取输出，用来判断项目是否在网络驱动器上。某些受限环境（沙箱 / 严格安全策略）禁止子进程管道，就会抛 EPERM。

解决办法：在**普通终端**里运行构建（不要用受限沙箱），或者改用 WSL。
</details>

<details>
<summary><b>手机浏览器里调用大模型报"网络请求被拦截"</b></summary>

见 README 的「如果提示"网络请求被拦截"」一节。
</details>

<details>
<summary><b><code>npm install</code> 报权限错误、写不进 npm 缓存</b></summary>

把缓存目录指到项目内：

```bash
npm config set cache ./.npm-cache --location=project
npm install
```
</details>
