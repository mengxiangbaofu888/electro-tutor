# 架构说明

> 面向想改代码或理解原理的人。产品需求见 `01-方案确认书-v1.md`。

## 一、总体架构

```
┌─────────────────────────────────────────────────────────┐
│  界面层  src/features/*        （按页面切分）             │
│  首页 / 材料 / 大纲 / 练习 / 答题 / 报告 / 错题 / 掌握度 / 我的 │
└───────────────┬─────────────────────────────────────────┘
                │ 只调用 services 层，不直接碰数据库和模型
┌───────────────▼─────────────────────────────────────────┐
│  业务编排层  src/lib/services/                            │
│  outline.ts  材料 → 知识点树                              │
│  quiz.ts     知识点 → 题目 → 试卷 → 答题记录               │
│  grade.ts    判分 / AI 批改 / 学习报告                     │
│  practice.ts 自进化粘合：掌握度、错题、复习、画像、微讲义    │
└──────┬──────────────────────────────┬───────────────────┘
       │                              │
┌──────▼──────────┐        ┌──────────▼─────────────────┐
│ 领域能力层       │        │ 基础设施层                  │
│ src/lib/srs/    │        │ src/lib/db/    IndexedDB    │
│ 掌握度/排程/     │        │ src/lib/llm/   大模型适配    │
│ 薄弱点/自适应    │        │ src/lib/extract/ 材料解析    │
│ （纯函数，可测）  │        │                            │
└─────────────────┘        └────────────────────────────┘
```

**分层原则**：
- `srs/` 和 `llm/json.ts` 是**纯函数**，没有 IO、没有 React，可以被单测直接覆盖。
- `db/` 和 `llm/` 是**基础设施**，只对外暴露简单接口。
- `services/` 是**唯一**把「数据库 + 大模型 + 算法」拼起来的地方，界面只跟它打交道。

## 二、数据模型

数据库名 `electro-tutor`，Dexie 版本 1。全部存储在本机 IndexedDB。

| 表 | 主键 | 索引 | 说明 |
|---|---|---|---|
| `materials` | id | createdAt, track, sourceType | 导入的原始材料（提取后的正文） |
| `outlines` | id | createdAt, track | 知识大纲 |
| `knowledgePoints` | id | outlineId, parentId, order | 知识点（树形，用 parentId 组织） |
| `questions` | id | outlineId, type, difficulty, createdAt, ***knowledgePointIds** | 题目；`*` 是 Dexie 的多值索引 |
| `papers` | id | createdAt, track | 试卷（只存题目 id 列表） |
| `attempts` | id | paperId, startedAt | 答题记录 + 报告 |
| `mastery` | knowledgePointId | dueAt, lastSeen | 掌握度与复习排程 |
| `mistakes` | id | questionId, resolved, lastWrongAt | 错题本 |
| `profiles` | id（固定 `'me'`） | — | 学习者画像 |
| `llmConfigs` | id | kind, createdAt | 模型配置（含 API Key） |
| `settings` | key | — | 杂项设置 |

**为什么知识点是枢纽**：题目、错题、掌握度、复习计划、补强讲义全部挂在 `knowledgePointId` 上。
这样一个知识点上的所有学习痕迹天然聚合，薄弱点分析和自适应出题才有依据。

**API Key 的存储位置**：`llmConfigs` 表。导出备份时**故意不导出这张表**，所以备份文件可以放心传网盘。

## 三、大模型适配层（`src/lib/llm/`）

### 3.1 协议
统一走 OpenAI 兼容协议：`POST {baseUrl}/chat/completions`。
预设 DeepSeek / 智谱 GLM / 通义千问 / 豆包 / Ollama，也支持任意自定义地址。

### 3.2 三种容错
| 问题 | 处理 |
|---|---|
| 服务商不支持 `response_format: json_object` | 收到 400/422 时自动去掉该字段重试一次 |
| 模型返回的 JSON 不干净（带代码围栏/前后解释/尾逗号/被截断） | `json.ts` 里五级降级解析：原文 → 去围栏 → 截取括号 → 去尾逗号 → 补齐未闭合括号 |
| 浏览器 CORS 拦截 | 检测到运行在 Capacitor 原生环境时，自动改走 `CapacitorHttp`（原生请求无跨域限制）；网页版则提示填代理前缀 |

### 3.3 错误翻译
所有 HTTP 状态码和网络异常都会翻译成人话，例如：
- 401 → "API Key 不正确或已失效，请重新粘贴"
- 404 → "接口地址不对，请检查是否填到了 /v1 这一层"
- `Failed to fetch` → "可能是浏览器跨域限制，或手机网络无法访问该接口"

### 3.4 上下文保护
材料在送进模型前会用 `truncateText()` 做**头尾保留、中段省略**（大纲 24000 字、出题材料片段 6000 字）。
保留头尾而不是砍尾巴，是因为材料的结论往往在结尾。

## 四、提示词设计（`src/lib/llm/prompts.ts`）

所有场景共用一个教师人设 `SYSTEM_TUTOR`，核心约定：

1. 技术必须准确，遵循国标（GB），不确定就说"需要查证"，**绝不编造参数或标准号**；
2. 面向零基础，先讲"为什么"再讲"怎么做"；
3. 只输出被要求的内容，不寒暄。

**六类提示词**：

| 函数 | 作用 | 关键约束 |
|---|---|---|
| `buildOutlineMessages` | 材料 → 知识点树 | 节点必须来自材料原文；最多 3 层、8~25 个；importance 1~5 |
| `buildQuestionMessages` | 知识点 → 题目 | 四个选项要对应**初学者真实会犯的错**；计算题必须给分步 rubric |
| `buildGradeMessages` | 单题批改 | 明确区分"思路对算错数""碰巧答对""概念混淆"三种情况 |
| `buildReportMessages` | 整卷报告 | 错因要挖到思维层面；建议必须可执行 |
| `buildProfileMessages` | 画像迭代 | **增量修正**不推翻；样本少时不做过度的推断 |
| `buildMicroLessonMessages` | 补强微讲义 | 固定四段结构；从他自己的错题出发讲，不从第一章讲起 |

**画像注入**：`renderProfile()` 会把学习者画像（水平、偏好讲法、薄弱点、错误模式、AI 摘要）拼进每个提示词。
这是"越用越懂你"的实现方式——不训练模型，而是让模型每次都带着你的档案工作。

## 五、自进化算法（`src/lib/srs/`）

全部是纯函数，无副作用、无第三方依赖。

### 5.1 掌握度更新 `mastery.ts`

| 参数 | 取值 | 理由 |
|---|---|---|
| EMA 系数 α | 0.3（`得分 = 0.7×旧 + 0.3×新`） | 单题最多撼动 30%，抗抖动；首次作答直接取得分率，避免从 0 慢爬 |
| 通过阈值 | 0.8 | 与批改的 `isCorrect` 判定一致 |
| 复习间隔 | 1 天 → 3 天 → `间隔 × 难度因子` | 经典 SM-2 递推；再乘 `0.9 + 0.2×得分率` 做微调 |
| 间隔上限 | 365 天 | 防止间隔膨胀到几年后 |
| 未通过 | `reps=0`，间隔固定 1 天 | 次日必复习 |
| 难度因子 EF | 初始 2.5，夹在 [1.3, 3.0] | SM-2 标准；额外强制"通过必 ≥ +0.05、未通过必 ≤ −0.15" |

### 5.2 遗忘衰减 `currentScore()`

```
当前掌握度 = 静态掌握度 × (0.3 + 0.7 × exp(−经过天数 / 稳定度))
稳定度     = max(1, 间隔天数) × (1 + 0.5 × min(reps, 12))
```

性质：刚复习完严格等于静态值；随时间单调不增；**永远保留 30% 不归零**。

### 5.3 薄弱点排序 `weakness.ts`

```
severity = 0.45×掌握度缺口 + 0.15×样本不足 + 0.2×遗忘程度 + 0.2×出错程度
```

- "样本够用" = 练过 4 次；"遗忘到顶" = 14 天没复习
- 从没练过的知识点固定给 0.8（高于一般薄弱点，低于四维度全崩的 ~0.96）
- `reason` 用中文人话解释，取权重最高的两个维度拼接；样本 ≤2 次时**优先说"样本太少"**，而不是对单题结果下结论

### 5.4 自适应出题 `adaptive.ts`

```
权重 = (1 − 当前掌握度)² + 0.15
```

- 平方放大差距；`+0.15` 保证完全掌握的点仍有权重（约最高值的 13%），**防止饿死**
- 不做归一化：新增知识点不会让全体权重漂移
- 因为用的是**带衰减**的当前掌握度，一个 60 天没复习的满分点，权重会自动回升到 0.64 左右

题量分配用**最大余数法**，保证各知识点题量之和**精确等于**目标题数，结果可复现。

## 六、判分策略

| 题型 | 判分方式 | 规则 |
|---|---|---|
| 单选 / 判断 | 本地 | 全对才得分；判断题会归一化"对/√/true/T"等写法 |
| 多选 | 本地 | 全对满分；漏选给一半；**错选 0 分**（国内考试惯例） |
| 填空 | 本地 | 多个空按比例给分；一个空支持多种可接受答案（用 `｜` 或 `/` 分隔） |
| 简答 / 计算 | 大模型 | 按评分点分步给分，返回 `scoreRatio` + 分步明细 + 知识缺口 |

**为什么客观题一定要本地判**：免费、离线、100% 准确、瞬时完成。只有主观题才值得花 token。

交卷流程会**边批边存**（每批完一题就写回数据库），中途失败不会让已批改的结果丢失。

## 七、关键设计取舍

| 决策 | 取舍 |
|---|---|
| 零后端 | 换来了零成本、零运维、隐私好；代价是网页版有 CORS 限制（App 版可解决）、无法做多人考场 |
| 用 IndexedDB 而非 SQLite | 网页和 App 共用一套代码；代价是移动端存储上限较小（对本场景够用） |
| 不训练模型，用画像注入实现"自进化" | 微调成本极高且手机跑不动；画像注入是同等效果、零成本的做法 |
| 主流转回真实判分 | 需要额外一次模型调用；换来"思路对算错数"能被正确区分，以及可申诉 |
| 提示词里反复强调"不编造标准号" | 电工领域编造 GB 标准号和参数危害很大，宁可让模型说"需要查证" |

## 八、怎么改代码

- **加一种题型**：`db/types.ts` 的 `QuestionType` 加枚举 → `QUESTION_TYPE_LABELS` 加中文 → `isObjective` 决定判分路径 → `ExamPage` 加答题控件。
- **接入新的大模型服务商**：`llm/presets.ts` 的 `PROVIDER_PRESETS` 加一项即可，协议层不用改。
- **调整算法参数**：`srs/mastery.ts` 顶部的常量（`PASS_RATIO` / `INITIAL_EASE` / `MIN_EASE` / `MAX_EASE`）和 `adaptive.ts` 的 `BASE_WEIGHT`。
- **改提示词**：只改 `llm/prompts.ts`，业务代码不用动。

改完跑 `npm run typecheck` 和 `npm run build`。
